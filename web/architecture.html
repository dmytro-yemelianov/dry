Finding Filter

This page is static and self-contained. It documents the current audit; it does not mutate project files or run the engine.

One Rust engine, thin adapters, and sharper contracts at the boundaries.

Dry is organized around a dependency-light Rust core. Python, TypeScript, CLI and browser surfaces mostly build or pass L1 operations into that core, then consume resolved L2 toolpaths. The highest-risk audit items are now addressed: segment kinds are typed, spline preview follows the emitter, optimizer behavior is shared, adapter parsing is centralized, and checked resolve guards bad physical inputs.

Module Relations

crates/core/src/resolve.rs

Owns state propagation, extrusion math, arcs, splines, channels and tool orientation. It is the main L1 to L2 lowering pass.

Feeds: simulate, verify, optimize, emit, codec.

ir.rs + units.rs

Define the L2 segment model and dimensional newtypes. This is the contract every frontend and backend relies on.

Wire value remains lowercase text; Rust contract is SegmentKind.

emit/

Converts L2 segments to g-code. Split by concern into parameters/writer logic, 5-axis kinematics, spline flattening and tests.

Depends on: resolve spline helpers and IR state.

verify.rs

Checks structural invariants and optional safety contracts: bounds, flow, speed, monotonic Z, cold extrusion and orientation magnitude.

Consumes: any segment stream.

optimize/

Holds L2 passes as separate modules: merge collinear, fit arcs and greedy travel reorder. All surfaces use the shared pipeline.

Shared via: optimize_pipeline.

codec/

Encodes compact DRY0 columnar and DRY1 chunked streaming binary forms, plus JSON/binary segment iterators. Split into format-specific modules and shared utilities.

DRY1 decodes bounded chunks; DRY0 stays readable for compatibility.

crates/cli, py, wasm, sdk/ts

Thin adapters around the core. They mostly parse JSON ops and expose core operations.

Shared helpers parse contract CSV and kinematics names.

web/viewer.js

Shared 3D preview and playback for gallery and Blockly pages. Uses resolved IR plus emitted g-code.

Spline preview now uses the same Catmull-Rom sampling as emit.

docs/ and README.md

Good architecture intent; README and task status now reflect the shipped v0 surface more closely.

Keep docs updates tied to feature landing.

Audit Findings

Solutions And Decisions

Keep the Rust core binding-free

The strongest boundary is already in place: PyO3 and wasm-bindgen sit outside dry-core. Keep new process logic in core, not in SDKs.

Promote IR kinds to a typed enum

Done: SegmentKind is a serde-compatible enum, so unsupported kinds fail at JSON/binary decode instead of falling through.

Define one motion-stream abstraction

Done for g-code emit via a writer API and for binary reads via DRY1 chunked decode. Random-access transforms still intentionally materialize a toolpath.

Expose preview-ready geometry

Done in the viewer and thumbnail renderer: spline segments are flattened with the same Catmull-Rom sampling as emit, and playback tracks g-code line indices.

Centralize boundary parsing

Done for contract CSV parsing and kinematics names through core helpers. A future typed JSON contract object would remove the remaining string boundary.

Update docs as part of feature landing

The project has outgrown the "nothing is built yet" status. Keep README, roadmap and task backlog synced with the tested implementation.
