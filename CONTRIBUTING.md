# Contributing to Dry

Dry is a proprietary, clean-room toolpath compiler. Contributions are accepted only from authorized
contributors covered by a written employment, contractor, assignment, or contributor agreement. This
guide covers the dev setup and the discipline CI enforces.

## The clean-room rule (read first)

Dry must never become a derivative work of **FullControl** (GPLv3). FullControl is used **only** as design
*inspiration* and a dev/CI *behavioural oracle* — never copied into Dry's source or shipped in a release.
See [`docs/CLEANROOM.md`](docs/CLEANROOM.md) for the full policy and
[`docs/17-provenance-and-licensing.md`](docs/17-provenance-and-licensing.md) for the provenance ledger.

By contributing you confirm the work is your own clean-room work (not ported from GPL sources) and that
you are authorized to submit it under the agreement governing your access. A pull request does not
itself grant or change any licence.

## Dev setup

```sh
# Rust engine + CLI
cargo build
cargo test --all

# Python binding (in a venv)
cd py && maturin develop && pytest tests/ -q

# TypeScript SDK / wasm
cd sdk/ts && npm ci && npm run build && npm test
```

## What CI enforces (run these before pushing)

```sh
cargo fmt --all --check          # formatting
cargo clippy --all-targets -- -D warnings   # NO #[allow] silencing — fix structurally
cargo test --all                 # unit + conformance + drift gates
python tools/validate_vectors.py conformance/vectors   # independent IR vector check
python tools/validate_reports.py .                     # report/profile schema check
```

The standing discipline (inherited from the fork): **clippy is `-D warnings` with no `#[allow]`** — fix
the structure, don't silence the lint.

## Conformance, vectors and goldens

Much of the suite is generated and **drift-gated** — if you change engine output you must regenerate:

- **IR vectors** (`conformance/vectors/`): `UPDATE_VECTORS=1 cargo test -p dry-core --test spec_vectors`
- **Report goldens** (`conformance/reports/`): `UPDATE_REPORTS=1 cargo test -p dry-core --test report_goldens`
- **Oracle corpora** (`conformance/{gcode,gallery,golden,profiles,roundtrip,simulate}/`): regenerated by
  `conformance/export.py` from the FullControl oracle (output only — see the provenance ledger).

Adding a public IR feature? Add a vector and update the spec (`docs/10-dry-ir-v0-spec.md`). Adding a
verification rule? Extend the `RuleId` registry in `crates/core/src/verify.rs`, the catalog in
`docs/11-profiles-and-reports.md`, and a report golden that triggers it.

## Pull requests

- Keep PRs focused; describe the change and how you verified it.
- Update the relevant `docs/` and `CHANGELOG.md` (`[Unreleased]`) when behavior or contracts change.
- Make sure the full CI list above passes locally.
- Behavioral changes (e.g. a verification rule's default severity) must be called out in the changelog.

## Releases

Releases are tagged (`vX.Y.Z`) and built by CI — see [`docs/12-releasing.md`](docs/12-releasing.md).
