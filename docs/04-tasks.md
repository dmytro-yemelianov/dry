# Dry — task backlog

Actionable tasks per phase. **Size**: S ≈ ≤1 day, M ≈ a few days, L ≈ 1–2 weeks. **Dep**: prerequisite
task ids. Each task is "done" when its **acceptance** is green (and, where relevant, its conformance gate
from `03-conformance.md`). Front-loaded on P0–P2 (the critical path); later phases are sketched and
refined as they approach.

Legend: `[ ]` todo, `[~]` partially landed, `[x]` landed for the current v0 scope. IDs are stable references.

## Phase 0 — Foundations & conformance harness

- `[x]` **P0.1** (M) Dependency-free Rust `core` crate with PyO3/wasm-bindgen isolated in adapter crates. *Accept (met):* `dry-core` builds without binding dependencies; workspace, wasm and PyO3 crates check separately.
- `[x]` **P0.2** (M) **Unit-typed Dry IR v0**: the L2 motion dialect carries typed quantities — `Length`/`Area`/`Volume`/`Feedrate`/`Time`/`Flow`/`Angle` (`crates/core/src/units.rs`), each `#[serde(transparent)]`. The cross-dimensional physics is defined once in the operators (`Length×Length=Area`, `Volume÷Area=Length`, `Length÷Feedrate=Time`, …) so a unit confusion in resolve/simulate/emit is a *compile* error. *Accept (met):* types compile; mixed-unit arithmetic does not compile; round-trips through serde byte-identically (the whole conformance suite + all three bindings stay green). *Deferred to P2.1:* the general toolframe orientation + the channel registry (they belong to the L1 path dialect).
- `[x]` **P0.3** (M) JSON + binary encodings of Dry IR v0 with a versioned header. `DRY0` (`Toolpath::to_bytes`) is the compact Arrow-style columnar body under DEFLATE (validity bitmaps for nullables, a kind dictionary); `DRY1` (`Toolpath::to_streaming_bytes`, now used by `dry pack`) stores compressed row chunks so CLI simulate/verify/emit can decode bounded blocks. `Toolpath::from_bytes` and `dry unpack` read both forms. *Accept (met):* `from(to(ir)) == ir` for every design (and empty/edge cases); `DRY0` on spiral_vase is **25.3× smaller** than JSON (1380 B vs 34841 B), well past the 3× gate; `DRY1` round-trips every conformance design and streams through the shared binary iterator.
- `[x]` **P0.4** (M) **Conformance export script**: fork → `conformance/{golden,gcode,gallery,profiles,roundtrip}/`. *Accept (met):* corpora generated + frozen; counts recorded.
- `[~]` **P0.5** (M) Conformance **runner** + CI matrix (native + wasm; fmt/clippy; SDK lint). **Landed:** Rust conformance tests, wasm smoke runner, TS/Python tests. *Remaining:* formal CI matrix definition.
- `[x]` **P0.6** (S) Pin the **math backend** (platform libm bindings) used by native + wasm; ban ambient clock/RNG. *Accept (met):* native↔wasm math parity test is green.
- **P0 exit gate:** extracted `core` reproduces fork `simulate` + Marlin `emit` byte-identical on the golden corpus, native + wasm.

## Phase 2 — Authoring: L1 dialect + lowering + Python SDK

- `[~]` **P2.1** (M) **L1 path dialect + channel registry**. **Landed:** the typed process channels — `temperature`, `fan`, `flow` (scales deposited volume), `tool` — authored as L1 ops, defaulted + propagated through `resolve`, riding each L2 segment (serde-omitted when unset, so motion-only IR stays byte-identical); plus the `Dwell` op (`G4` emit + simulated time) and a `cold-extrusion` verify rule. The codec round-trips the channels; arcs already carry centre/clockwise. *Accept (met):* channels typed + defaulted; conformance byte-identity preserved; channel-bearing IR round-trips through the binary codec. The channels are exposed in all front-ends (Rust `Op`, Python `.temperature()/.fan()/.flow()/.tool()/.power()/.orient()/.dwell()`, TS the same). The **spindle/laser power** channel (`Segment.power`, the `Power` L1 op, GRBL `S`/`M3`/`M5`) landed later, in P5.4. The **toolframe orientation** also landed: `Segment.orientation` (tool-direction unit vector, `None` ⇒ +Z), the `Orient` L1 op, codec round-trip, an `orientation-not-unit` verify rule, and `.orient(i,j,k)` in every SDK — so non-planar / 5-axis is now a first-class IR property. The **5-axis target lowering** also landed: `emit` with `five_axis` derives rotary `A`/`B` words (degrees) from the toolframe orientation by a documented AB-head convention (`B = atan2(i, k)`, `A = atan2(j, hypot(i, k))`), emitted only when they change; CLI `dry emit --five-axis`. Default emit stays 3-axis (orientation dropped → byte-identical). *Deferred to later P2.x:* `Spline`/`Clothoid`/`ToolChange` path nodes and alternate rotary kinematics (AC/BC, table-vs-head). (L2 optimisation: `merge_collinear` has landed — see P3.1.)
- `[x]` **P2.2** (L) `resolve: L1 -> L2` lowering (deposition math + state propagation: running toolframe, extruder e-ratio, channel propagation) as a **pure pass**. *Accept (met):* hand-written L1 designs resolve to L2 that simulate/emit to the gated output; checked resolve validates physical inputs at binding boundaries.
- `[x]` **P2.3** (M) `expand_features: L0 -> L1` with bounded `Feature@pose`, ordered `Group` and compositional `Repeat`. **Landed:** the Rust pass accepts a coordinate-local L1 op list, XYZ translation and planar Z rotation; transforms moves/arcs/splines/tool orientation; inherits local axes deterministically; rejects undefined local positions and transformed manual G-code; and enforces node/depth/op limits. Process/channel state retains normal ordered L1 semantics. Python and TypeScript expose logic-free `FeatureProgram`/`feature`/`group`/`repeat` builders over the same Rust implementation. Full 3D named frames remain D1.3. *Dep: P2.1. Accept (met):* repeated/placed graphs expand to the same L1 and resolved L2 as hand-written equivalents across Rust/Python/TypeScript; nested transforms, failures, limits and wire round-trips are tested.
- `[x]` **P2.4** (L) **Python authoring SDK** (FC-flavored builders emitting L1). *Accept (met):* authoring square/arc/channel/spline designs lowers to gated g-code and tested metrics.
- `[x]` **P2.5** (L) Reimplement (clean-room) the **27 fork gallery designs** in the new SDK as the authoring conformance suite (geometry-level comparison, not just metrics — per `03`). **Landed:** 28 oracle-output fixtures cover all 27 registry designs plus a distinct `overhang_challenge_plus` website case; the exporter separately guards the fork's 26-case `_SMALL` matrix and its known gyroid omission. *Dep: P2.4, P0.4. Accept (met):* each design lowers+emits to match the fork within the documented tolerance and passes its declared invariants.
- **P2 exit gate:** every gallery design authored in the new Python SDK reproduces the fork's output + invariants.

complete. Each D1 item below is an epic; estimate and execute its merge-sized work packets from

## Mathematical assurance workstream FM1

FM1 is specified in
[`21-mathematical-assurance-plan.md`](21-mathematical-assurance-plan.md). It has an independently useful
v0 lane and a D1-dependent future-language lane. A checked abstract theorem is not enough for a claim
about Rust `f64` behavior: the relevant task must also land its numeric bound and implementation
refinement evidence.

- `[~]` **FM1.1** Assurance constitution and Lean tooling spike. **Landed and CI-green:** accepted ADR 0001; schema-backed claim registry and independent validator; pinned Lean 4/Mathlib project; checked exact-real planar transform composition and ordered-fold determinism proofs; dedicated CI job. **Remaining:** record an independent clean-checkout reproduction before closing the milestone. *Dep: P4.3 (met). Accept:* planar transform composition and deterministic fold proofs build in CI; every registered claim names assumptions, relation, semantic version and implementation link.
- `[~]` **FM1.2** Quantity, syntax and well-formedness kernel. **Landed:** exact dimension exponent algebra, dimension-indexed quantities, same-dimension units with positive rational scales, canonical conversion/normalization coherence, a checked deposition-dimension identity, the published L2 v0 logical syntax with structured failures and decidable well-formedness, acceptance/rejection equivalence, serializer-neutral logical equality, and executable TSV plus schema-validated JSON boundary fixtures. **Remaining:** L1 syntax after its public contract is frozen, an independent Rust consumer/refinement check for the logical fixtures, and future public quantity vocabulary after D1.2. *Dep: FM1.1; future quantities also depend on D1.2. Accept:* normalization/coherence/dimension theorems and validity decision equivalence are checked.
- `[~]` **FM1.3** Transform, feature and frame proofs. **Landed for the bounded planar subset:** generic `Feature`/ordered `Group`/`Repeat` expansion semantics; source-order and repeat decomposition laws; exact expanded-operation counts; operation/node/depth budget preservation; deterministic traces; exact-real pose action on abstract points, vectors and invariant operations; checked success/first-error semantics for feature names, finite/non-finite poses, tool, partial-coordinate move, arc including finite centres, spline, finite orientation and manual-code operations; 28 exact schema-valid Lean-generated fixtures, two structural quarter-turn fixtures, thirteen selected local native numeric fixtures and three selected end-to-end nested application fixtures consumed independently by Rust; six additional exact-rational orientation fixtures independently check the production nonzero resolver gate and unit/non-unit verifier classification; a pinned source hash and 35 compiled `features.rs` mutations, each killed by its named fixture in CI, including reversals of both Feature and Repeat composition operands, nine local native numeric faults and three nested application faults; nine registered feature/implementation claims, with composition-tree shape, nested application and orientation-contract refinement checked only for their committed corpora. **Remaining:** finite-width counter overflow, arbitrary-input refinement of the binary64 unit tolerance and nonzero magnitude calculation, normalization policy, mutation coverage outside the pinned bounded surface, universal native/wasm numeric refinement, then `SE(3)` poses and named frame graphs after D1.3. *Dep: FM1.2, P2.3; full scope D1.3. Accept:* transform action, repeat, ordering, budget, determinism and frame-resolution/rejection theorems pass with Rust refinement fixtures.
- `[~]` **FM1.4** Floating-point and curve error budgets. **Landed for feature expansion:** a schema-backed manifest classifies 13 pose, inheritance, angle, trigonometric, composition, point/arc/orientation, input-rejection, epsilon-policy and pass-through boundaries; pins both the implementation and complete `Op` input domain by source hash; verifies unique source anchors and reciprocal claim links; and records unresolved universal implementation refinement and policy boundaries explicitly. Arc-centre and orientation non-finite inputs fail before arithmetic in checked field order. A linked provisional binary64 profile fixes nine proof-precondition limits, the Rust/native+wasm toolchain boundary and seventeen named budgets. A parametric Lean rounding model proves the local-operation formulas for vector/point application and transform composition; a scoped round-to-nearest/ties-to-even instantiation includes gradual underflow and checks primitive ceilings `2^-32` for multiplication and `2^-30` for addition/subtraction, yielding local component ceilings `2^-29` for vector/rotation XY, `2^-28` for point/translation XY and `2^-30` for point/translation Z. The exact binary64 PI rational and Mathlib real-π bounds establish `2^-46` radian error for the ordered degree conversion over ±360° and a strict `[-7, 7]` `libm` input envelope. A pinned release/source ledger imports `libm` 0.2.16's one-ULP MPFR sine/cosine policy as an explicit conditional contract rather than treating its sampled tests as a proof; Lean derives a `2^-51` same-input bound and an end-to-end `2^-45` coefficient bound. A sequential same-pose repeat theorem composes those results through at most 100,000 checked composition graphs, bounding coefficient components by `2^-10`, XY translation components by a deliberately conservative `2^29` mm and Z by `2^-13` mm. A parenthesization-preserving binary-tree theorem generalizes the result to mixed nested transforms without assuming binary64 associativity; it retains the `2^-10` coefficient and `2^-13` Z ceilings and publishes a conservative `2^30` mm XY ceiling. New application theorems propagate that tree error through one final point/Arc-centre or orientation graph, yielding conservative component ceilings of `2^31` mm for point/Arc XY, `2^-12` mm for point Z and `2^-8` for orientation XY, with orientation Z exact. For an exact unit orientation, the component result now proves the computed vector is nonzero and its unoriented angular error is at most `1/4` radian. A selected-path bridge proves that Feature and Repeat descent constructs exactly that parent-first tree shape and mutation-checks it over two Lean-generated quarter-turn cases. A second Lean generator exports four cardinal pose, three one-step composition, two point, two Arc-centre and two orientation-vector cases with exact power-of-two budgets; the native consumer checks real-π intervals, cardinal trig results and arbitrary-precision exact-dyadic operation graphs, while nine mutations break the corresponding Rust expressions. A third generator exports three nested `Repeat → Repeat → Feature` programs covering final Move, Arc-centre and orientation application; Rust checks four feature occurrences under ceilings stricter than the published tree budgets, and three named mutations corrupt that end-to-end path. Sixteen budgets are bounded and the manual epsilon remains policy; ten registered abstract numeric claims remain universal numeric-refinement-pending, two bounded native-corpus claims are refinement-checked and the finite orientation-contract corpus is refinement-checked without claiming a general numeric equivalence. **Remaining:** replace the imported `libm` premise with exhaustive source-level verification, tighten the repeat/tree/application translation and angular bounds, generalize nested native/wasm values outside the cardinal corpus to the profile, rounding, libm, operation-range, exact-unit and final-application premises, review/accept and optionally runtime-enforce the profile, then cover sampled splines. *Dep: FM1.2–FM1.3. Accept:* no Rust geometry claim inherits an exact-real theorem without a checked bound.
- `[~]` **FM1.5** Resolve, simulate and verifier proofs. **Landed for orientation/channel resolution:** executable Lean state semantics, generated schema-checked sequence fixtures, native Rust consumers, and scoped resolver mutation gates. **Landed for deposition:** exact-rational equations plus a four-case Lean-generated native Rust refinement corpus (`FM1.DEPOSITION.NATIVE.REFINE.CORPUS`). **Landed as abstract models only:** an append-compositional simulation fold and soundness of five exact-rational verifier predicates. **Remaining:** binary64 bounds and Rust refinement for simulation/verifier models, coverage correspondence to every claimed production rule, and streaming/materialized equivalence. *Dep: FM1.2–FM1.4. Accept:* the supported resolver subset produces well-formed L2; every claimed verifier predicate is coverage-aware and refinement-tested.
- `[~]` **FM1.6** Optimization contracts. **Landed as an abstract model only:** the merge constructor stores additive length and volume, registered as `FM1.OPTIMIZATION.MODEL.SEMANTICS`. **Remaining:** production merge preconditions, the actual observation relation, binary64/Rust refinement, and legal pipeline composition/gating. *Dep: FM1.3–FM1.5. Accept:* no pass uses an unqualified “semantics-preserving” claim.
- `[~]` **FM1.7** Codec and compatibility proofs. **Landed as a serializer-neutral model only:** a three-field segment encoding has an exact list round trip. **Remaining:** actual JSON/`DRY0`/`DRY1` layouts, row/column equivalence, chunk independence, versions, malformed-input rejection, resource bounds, and Rust/independent-reader refinement. *Dep: FM1.2. Accept:* checked logical theorems plus Rust and independent-reader refinement over frozen/generated vectors.
- `[~]` **FM1.8** Capability, backend and lift refinement. **Landed as an abstract model only:** a three-bound capability predicate fails closed when feedrate, flow, or temperature exceeds the modeled profile. **Remaining:** production capability extraction/refinement, generic backend relation, FFF and selected non-FFF target proofs, lift/recovery observations, opaque/loss barriers, and the conditional compiler theorem. *Dep: FM1.2–FM1.5, D1.6, D1.8, D1.9. - **FM1 exit gate:** not met. Abstract proofs and five implementation-scoped corpus claims are registered, but universal numeric/Rust refinement, actual codec/optimization/backend composition, release reproduction, and independent review remain open.

## Core hardening workstream H1

Findings from the 2026-07-31 core audit (`docs/superpowers/specs/2026-07-31-core-hardening-audit.md`):
five parallel subsystem audits over `units`, `resolve`/`engine`, `emit`/`gcode`, `verify` and
`generate/tpms`, hunting the seven defect classes found and fixed in `generate/pocket.rs`. Every item
was confirmed against the code, most by execution. The unifying finding: **non-finite quantities could
reach metal** — `num()` printed `NaN`/`inf` verbatim as g-code words, and `dry emit` never runs the
verifier, so `emit` is the last gate.

- `[x]` **H1.1** (M) **Emit safety gate** — the emitter must reject what it cannot faithfully represent. **Landed:** non-finite values no longer reach g-code words; five-axis orientations are normalised and zero/non-finite magnitudes rejected (a non-unit orientation silently displaced the *linear* axes, and the `Ac`/`Bc` and `Ab` models disagreed on identical input); RS-274 span rewrites no longer splice `M83`/`M82`/`G92 E`/`M221` into CNC programs (an unknown M-code aborts on LinuxCNC/Fanuc, and the guarding test passed with the bug present); `CncFrame` validates `wcs ∈ 54..=59` and `spindle_rpm > 0` on the `pub`/`Deserialize` path, not only through `Profile`; an `Arc` with an undefined endpoint is refused instead of emitting a bare `G3 I.. J..`, which is a full 360° circle on RS-274. Review then found the slice had hardened the emitter without following the refusal to where it surfaces, and a second pass closed that: the CLI no longer leaves a truncated program on disk (it renames into place only on success), `emit_step_nc` is gated and its sidecar is no longer written before the program is known emittable, and both bindings now raise instead of returning `[]` for refused IR — reachable from three ops of ordinary JSON, and previously rendered as a successful blank program by `web/viewer.js` and `sdk/ts`. `emit()` keeps its signature as a transitional guard and is now `#[deprecated]` in favour of the fallible `emit_stream`. *Accept (met):* invalid IR is refused at every emit surface; goldens and conformance corpus byte-unchanged. *Breaking:* refused IR raises on the wasm/PyO3 surfaces where it previously returned an empty array (recorded in `CHANGELOG.md`). *Deferred follow-ups from the two review rounds:* CI runs `cargo test` in debug only, so the shipping release branch of the `emit()` guard is exercised only by a manual `--release` run — a single `--release` run of `emit_rejects_unrepresentable` in CI would close it cheaply; source-echoed extruder M-codes (`M104`, `M106`, `M221 S90`) still reach an RS-274 rewrite through `splice_motion_spans`' echo contract (claim now scoped, behaviour deliberately unchanged); an arc whose named endpoint coincides with its start still emits a full 360° circle — a `verify` rule would close the ergonomic half of that hazard; `hypot`-style magnitude in `unit_orientation` (`[1e200,0,1e200]` overflows to `inf` and is refused despite a well-defined direction); the finite half of the Klipper dwell saturating cast; RobotKRL's rotary `C` colliding with the arc `C` offset and `CIRC` losing arc direction; and `spec/dry-ir-v0.schema.json` does not record that a `kind:"arc"` segment requires non-null `end[0]`/`end[1]`, so schema-valid IR is now emit-refused.
- `[x]` **H1.2** (M) **Ingress validation** ([#184](https://github.com/dmytro-yemelianov/dry/issues/184), closed) — close the paths that feed non-finite and out-of-domain values into the IR, so H1.1's gate is defence in depth rather than the only defence. Binary codec `Reader::f64` accepts any bit pattern (`DecodeLimits` bounds sizes, never values, though hostile input is explicitly in the threat model); `flow_ratio_from_percent` detects a non-finite `M221` and returns it anyway; `ResolveParams.retraction_distance`/`_speed` are never validated and are deserialized from caller JSON on every binding (a negative distance flips a retract into an unretract); zero and negative feedrates are accepted, and `simulate` silently drops zero-speed segments from every metric while making them immune to the max-flow ceiling. Add a checked `Length::try_mm` and give the newtypes a value invariant. **Landed:** `Reader::f64` refuses non-finite bit patterns in both binary forms (`CodecError::NonFinite`); every G-code word is checked at the scanner and both ratio helpers are total; `ResolveParams.retraction_distance`/`_speed` are required finite and positive; the 3MF importer refuses non-finite, negative and missing-but-required attributes; a negative feedrate is refused at ingress and un-timeable in `simulate`. Review then found the slice had gated every *parsed* value while `Length::mm`'s new `debug_assert` constrains the *constructed* one, so the invariant was asserted but not established — the arithmetic in between overflows finite input, and a second pass closed that seam on all three ingress paths: the G-code importer builds every quantity through `Length::try_mm` or an explicit check (`point_dist`, the `G20` unit conversion on coordinates/feedrate/extrusion/`G92`, the `M221` flow product, and a `filament_diameter` with no finite cross-section), the 3MF importer checks its squared delta, and `resolve_checked` validates the toolpath it *produced* — `validate_design` bounds coordinates only by `is_finite`, and two ops 1e200 apart square to `Area(inf)` that `Area::sqrt` returns as `Some(Length(inf))`. `dia` must now also give a finite non-zero bead cross-section. Zero-speed accounting is deliberately unchanged (see H1.5). *Accept (met):* the five ingress paths — binary codec, JSON codec, G-code import, 3MF import, and design JSON through `resolve_checked` (which the `generate/` L1 generators and both bindings route through) — admit no non-finite quantity into the IR; goldens and conformance corpus byte-unchanged. *Not total in debug builds:* `resolve_checked`'s finiteness refusal is a postcondition, so a design whose lowering overflows to NaN (the same ~1e308 spline) panics at `units.rs:123` (`Length::mm(NaN) is not finite`) *inside* `resolve_unchecked` in a debug build, where a release build returns the `Err` cleanly. This predates the second pass (it arrived with `Length::mm`'s assertion in `e1fa2ac`) and does not weaken the accept clause — a panic puts nothing in the IR — but a debug-built PyO3/wasm binding aborts where a release build raises. *Breaking:* recorded in `CHANGELOG.md`, including `export_3mf_xml` now writing `feedrate="0.0"` for a moving zero-speed segment. *Deferred follow-ups:* `try_encode` is not tightened, so a `.dryc` written by an older version from non-finite IR is now undecodable but still writable; `resolve.rs:361`'s `dist` falls back to `Length(f64::NAN)` when `Area::sqrt` returns `None`, and that fallback is **live, not dead** — H1.3 must not delete it as unreachable. `Area::sqrt` (`units.rs:153`) returns `None` for a **NaN** area as well as a negative one, because `NaN >= 0.0` is false; in a **release** build a spline with ~1e308 control points reaches it (`catmull_rom` overflows → `Length::mm(NaN)` at `resolve.rs:684` with the `debug_assert` compiled out → `sq` is NaN → `sqrt()` is `None` → the fallback fires). Nothing escapes — `require_finite_toolpath` turns it into `segments[i].length resolved to NaN` — so what H1.3 should reconsider is the shape of the fallback, not its reachability; and `spec/dry-ir-v0.schema.json` still records no `minimum` on `Segment.speed`.
- `[x]` **H1.5** (S) **Formal model: negative feedrate divergence** ([#191](https://github.com/dmytro-yemelianov/dry/issues/191), closed) — surfaced while implementing H1.2. `formal/Dry/Semantics/SimulateMetrics.lean` guarded `segmentMotionTime` on `seg.speed = 0`, so at `speed = -60` it fell through to the `else` branch and produced a **negative duration** that flowed into `totalTime`. Rust rejects a negative feedrate at ingress (H1.2), so no native run could reach that branch — but the model defined it. **Landed:** the guard is now `seg.speed ≤ 0`, which removes the branch rather than leaving the two sides disagreeing about a case only one admits. Verified a no-op for the refinement corpus exactly as predicted: its speeds are 60, 30, 0, 30, 0, 30 and {40, 25, 20, 0} with no negative case, and `check_proof_fixtures.py` still reports its 7 simulate-metrics cases green. Zero-speed swallowing is deliberately unchanged — the Lean model specifies it, and ADR 0002 Decision 6 makes the artifacts authority. *Accept (met):* the Lean model and the Rust ingress agree on speed validity.
- `[x]` **H1.6** (S) **Clamped-layer bead declaration** ([#187](https://github.com/dmytro-yemelianov/dry/issues/187)) — H1.4 T2 made *adaptive* TPMS layers declare the bead height they occupy, but the treatment is gated on `adaptive`, so a **non-adaptive** clamped top layer still over-declares. Measured 1.40x at the generator defaults and up to **99.95x** at `layerHeight 0.5997`, because `DEGENERATE_TOP_LAYER_FRACTION = 0.01` merges only sub-1% remainders — so T2 replaced an unbounded bug with a 100x cliff, on the default path. The first layer is the same question at the other end (it keeps the configured `beadHeight` rather than deriving a gap from `z0`), and `beadHeight` is silently discarded from layer 2 onward under `adaptive`. One task owns all three. Deliberately **not** folded into T3, whose only correctness check is attributing its op-count delta to removed coincident pairs. **Landed:** the per-layer declaration is ungated, so a clamped top layer declares its true gap on both paths (option (a) of #187 — emit the extra `Op::Geometry` — was chosen by the repo owner over redistributing the remainder); `beadHeight` is preserved as a ratio (`gap × beadHeight / layerHeight`) instead of being discarded from layer 2 onward, which also makes the first layer the nominal-gap case rather than a special case; and `DEGENERATE_TOP_LAYER_FRACTION` is **kept** — an honest declaration does not make a degenerate layer emittable — now pinned from both sides by a 0.9%/1.1% boundary test, where the previous 0.03% fixture killed no mutant of the constant. **Review found the boundary analysis one case short, and the fix wave closed it:** ungating fed the declaration from the skipped-layer mechanism, where a layer that traces no contour emits nothing and does not advance the reference Z, so the next depositing layer's gap spans every skipped layer. Under `adaptive` that was H1.4 T2 behaviour; ungating made it the default path. Measured through `try_tpms_ops` at default `minPathLength`/`samplesPerCell`: `neovius, isoLevel 1.0, layerHeight 0.2` declared `[0.2, 3.2, 0.2]` (**16x**, and +20% of filament through `resolve_checked` — 47.2735 → 56.7330 mm), `neovius, isoLevel ±0.8, layerHeight 0.28` alternated 0.28/0.56 (2x), `schwarz-p, isoLevel 1.0, layerHeight 0.28` reached 1.4 (5x). **Decided and implemented:** such a layer declares the **nominal bead height**, not the span — the gap is only a bead height when it is material actually stacked beneath, and across skipped layers nothing was deposited, so the nozzle lays one ordinary bead onto whatever is below rather than a 3.2 mm column into air. Declaring the span is a self-consistent lie of the kind this task removes, and a larger one than the defect it fixed; no verifier catches either (no rule relates deposited material to geometry — H1.3). Also corrected in the fix wave: the *stated mechanism* for keeping the constant was wrong (the decision was not). A sub-half-step remainder in the **layer height** is absorbed by rounding before the fraction test runs — `layerHeight 1.99999995` on a 12 mm block emits `[1.99999995, 2.0]` and resolves, because `base_layer_zs` compares the already-rounded `zs.last()` against `height` under `abs() > EPS`. The real trigger needs a **non-grid-aligned block height**: with the constant deleted, `cellSize 12.0000003, layerHeight 2.0` emits `[2.0, 0.0]` and `resolve` refuses it. (Units: `QUANTUM = 1e6` is the reciprocal of the step, so half the *step* is 5e-7 mm, not "half the QUANTUM".) Op-stream delta re-measured across 28 option sets after the fix: with a **grid-aligned** `layerHeight`, exactly +1 op on every clamped case (default 21634 → 21635), byte-identical for adaptive and exact-multiple jobs; a `layerHeight` off the 1e-6 mm coordinate grid is **not** +1 — `layerHeight = 1/3` on 12 mm goes 2463 → 2488 (+25), 26 declarations across 37 layers alternating `0.333333`/`0.333334`, which is honest and deliberately unsuppressed; and byte-identical everywhere once `Op::Geometry` is filtered out. *Dep: H1.4 T2. Accept (met):* on both paths every emitted layer declares the height it occupies, with two **documented divergences** — the first emitted layer declares the configured `beadHeight` (it has no layer beneath it to measure against, `resolve` has no first-layer convention to match, and `z0` is nozzle Z rather than a guaranteed plate gap), and a layer following one or more skipped layers declares the nominal bead rather than the Z it spans (above). *Breaking:* recorded in `CHANGELOG.md`, scoped to wasm, PyO3, the TS SDK and the `pub` Rust API. *Known extreme-value gaps, recorded not closed* (all three outside physical ranges, and all three the generator emitting IR its own `resolve` refuses — the class H1.1/H1.2 closed — while `tpms_ops_json` returns the bad stream with no refusal at all): (1) the `beadHeight` ratio can round a declared height to `0.0` — `layerHeight 0.5997, beadHeight 0.00004` emits `[4e-5, 0.0]` and `resolve_checked` refuses with `height must be > 0`; pre-change the same options validated OK. (2) `DEGENERATE_TOP_LAYER_FRACTION` does not close that hole for `layerHeight < ~5e-5` — `cellSize 0.1000003, layerHeight 1e-5` emits `[1e-5, 0.0]` and is refused. (3) `round()` overflows for a huge bead — `beadHeight 1e307` emits `[1e307, inf]` and is refused with `height must be finite`. A later slice should close all three in the `reject_vacuous` idiom (ADR 0002 §4): refuse in the generator rather than emit IR the next stage rejects.
- `[x]` **H1.7** (M) **`web/tpms.js` divergence — DECIDED: delete and delegate to wasm** ([#188](https://github.com/dmytro-yemelianov/dry/issues/188)) — a 638-line browser reimplementation with zero engine references that carries every defect H1.4 fixed, and is not merely behind the engine: it has options Rust does not have (`pathMode`, `arcFit*`) and a divergent budget sentinel. `web/index.html` generates through it, so the browser demo ships the vacuous programs wasm/PyO3/TS now refuse. **Decision (2026-07-31):** delete the reimplementation and delegate to the engine over wasm, as `sdk/ts` already does — `pathMode` and `arcFit*` are dropped rather than ported, since they have no engine equivalent and no stated requirement. *Accept:* `web/tpms.js` is gone, the browser generates through the engine, and `web/blocks-regression.mjs` is re-baselined against the new output.
- `[ ]` **H1.3** (L) **Verify strengthening** ([#185](https://github.com/dmytro-yemelianov/dry/issues/185)) — `verify` is a strong *contract* checker and a weak *well-formedness* checker, and downstream assurance arguments lean on it as the latter. No rule compares segment *i*'s end to segment *i+1*'s start, and the emitter writes endpoints only — so a gap produces no repositioning move and the machine cuts straight across it (which also makes `monotonic-z` intra-segment only). No rule relates deposited material to geometry, so an 8000× under-extrusion passes. Sign and zero are unchecked; a zero-length extruding move disables three rules at once. `junction-velocity` measures a speed *difference*, not a direction change, so it misses the constant-speed 90° corner it is named for — and disagrees with `optimize/adaptive_speed.rs`, which computes the right quantity under the same name. Under `Contracts::default()` only 5 of 18 rules can fail, yet 8 call sites use `report.ok()` as an assurance claim; a vacuous pass is byte-identical to a real one. *Dep: H1.2. Accept:* a clean `verify` certifies well-formedness, and reports record what was inspected.
- `[ ]` **H1.4** (M) **TPMS hardening** ([#186](https://github.com/dmytro-yemelianov/dry/issues/186)) — see `docs/superpowers/plans/2026-07-31-tpms-hardening.md`. Accept:* every documented parameter range either produces material or is refused.

- `[ ]` **H1.8** (S) **TPMS T1 residuals** ([#189](https://github.com/dmytro-yemelianov/dry/issues/189)) — the degenerate-perimeter class is narrowed, not closed (an inset one epsilon below the gate still yields 176 coincident extruding moves with zero extruded length that `verify` reports clean, and `reject_vacuous` exempts any `perimeter: true` job unconditionally); the refusal message blames `minPathLength` at its *default* value on 6 of 10 surfaces at exactly the isoLevel values users tune; the vacuity predicate is satisfiable by 0.021 mm of total extrusion; and the `perimeterInset` gate refuses 160 of 4,000 fuzzed configs that previously emitted real material, naming an option the caller never set. *Dep: H1.4 T1. Accept:* a program that deposits no usable material is refused, and every refusal names the option the caller actually set.
- `[ ]` **H1.9** (S) **Binding-level rejection tests** ([#192](https://github.com/dmytro-yemelianov/dry/issues/192)) — four slices (H1.1, H1.2, H1.4, H1.6) narrowed acceptance on wasm/PyO3/TS with no binding-side test exercising any of it.
